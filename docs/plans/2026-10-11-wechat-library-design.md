# 公众号原始表情素材库与关联互动

范围：仅 https://mp.weixin.qq.com/s/CaQ-fa957yZ8h8b_sEHxwA 当前文章。用户已明确，不抓取公众号其他文章，不再生成式重绘人物。

## 先确定结构

沿用当前 Windows WPF 项目，不创建新应用仓库。选择数据驱动的素材库：比把数百动作写进 PetState 枚举更容易筛选删除，也比直接随机播放所有图片更能表达互动。

- `content/wechat/originals/`：按文章顺序稳定编号的原文件，记录来源 URL、SHA256、尺寸、帧数；不重绘、不覆盖。
- `content/wechat/compiled/`：从原 GIF 按 disposal 规则合成的完整帧及帧时长，PNG 图集与缩略图。当前选择完全保留原 RGBA 像素，不删除文章素材本来的白底、文字、道具或场景；极短/缺失延迟设 20ms 下限。静态待机单独从已批准的样稿裁切，只清理与边缘连通的白色背景，保留封闭轮廓内的白色人物。
- `content/wechat/catalog.json`：全部素材目录、角色类别、语义名称、是否已目视确认。角色未知的素材可预览，不能擅自参与自动互动。
- `content/wechat/interactions.json`：独立互动规则。单图已经含两只角色时，作为双人整体播放；不同单人图只有确认语义互补后才配对，按发起、回应、结束的时序播放。
- WPF `StickerLibrary`：读取目录、按需缓存图集、播放真实帧时长，避免启动时加载数百动画。
- WPF 素材管理窗口：编号搜索、分类、原动画预览、桌面播放、停用与恢复。停用写入用户设置，不删除原始文件；请求删除时可凭编号准确处理。

## 关联模型

双人组合：两只可见且空闲 → 靠近 → 同步显示原始双人动画 → 恢复两只独立角色。保留原图的左右身份，点击/拖动任意角色能中断互动。拖拽、甩动、手动菜单和隐藏角色优先，不强行继续。

双素材回应：发起角色原动作 → 对方原动作回应；可选靠近。语义关联需要目视确认，不以颜色、文件相邻或名称猜测动作。互动定义引用稳定素材 ID，任一素材被停用，依赖互动同时不可用；播放中停用立即结束。

静态图片保持静态，不生成中间帧；GIF 保持原始时序。没有合适素材的动作不补画。文章广告、二维码等非表情独立归类并默认停用，保留来源记录供复核。

## 验证与交付

清点正文图片与下载成功/失败数，校验哈希；验证每个图集帧数量、时长、矩形边界与源文件对应。目视检查编号联系表并记录分类与具体互动依据。构建 WPF，运行素材加载、禁用依赖、中断与恢复的冒烟检查，测试文件用后删除。保留原有设置和已禁用的启动项。
