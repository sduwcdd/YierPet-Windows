# 一二和布布：语音接入、素材准备与模型保存

v0.0.3 提供 **GPT-SoVITS 本机接口接入**：两位角色分别配置声音，输入中文台词，生成、试听和下载 WAV。**已使用用户通过 voice-review.json 确认的全部 24 段素材，完成两位角色的本地首版 v2 模型训练。** 发布包已包含语音工坊和预生成的健康提醒音频。训练权重、参考录音、源音视频和 Python 推理环境保存在开发者本机，不随仓库或 EXE 分发；其他电脑生成新台词需自行准备并配置。

## 1. 快速开始：不必每次选择模型

### 1.1 只想听健康提醒

更新到 v0.0.3 后，右键角色 → **健康提醒**：

1. 勾选想要的提醒类型：久坐、喝水、深夜关怀或摸鱼检测。
2. 保持 **提醒时自动说话** 开启。
3. 点击 **试听一条提醒**，立即检查文字气泡和语音。它从已启用类型中选择第一类，随机播放该类的一句；全部关闭时会提示先启用。
4. 想保留文字但不出声，取消 **提醒时自动说话**。此操作也会停止正在播放的提醒。

现有 16 句台词均准备了一二、布布两个音色，共 32 段语音；每段同时保留原音和轻度清晰化版本，共 64 个 WAV。配音略过睡觉装饰符号 `zzZ`，气泡保留原文。提醒使用预先生成的本地文件，**不需要启动 GPT-SoVITS，不需要联网，不需要训练模型**。

沿用现有提醒规则：一二可见时由一二说；隐藏一二、只显示布布时由布布说。它不会让两位同时说同一句。健康提醒仍按原时间和开关触发，不会因增加语音而更频繁。语音工坊正在生成或试听时，提醒只显示文字，避免声音重叠；之后不会补播过期提醒。

右键 → 健康提醒与语音工坊中的自动说话选项共用同一份设置。从右键菜单返回语音工坊时，会自动刷新提醒开关；也可点击 **重新读取配置**。改变语音工坊的模型不会重做已经配好的提醒音频；更换提醒音色需要重新生成对应素材。

### 1.2 自己输入新台词

右键角色 → **语音工坊 · 生成 / 下载**，或在表情库顶部点 **语音工坊**。源码构建可传入 `--voice` 参数直接打开。

1. **检查声音。** 本机已有保存的配置时自动载入；没有配置但装有默认预设时自动填充。卡片会显示角色、模型文件名和参考录音文件名。当前本机默认组合是一二 GPT 10 轮＋基础 SoVITS，布布 GPT 10 轮＋SoVITS 2 轮。
2. **检查准备情况。** 默认开启按需加载，本机已配置的环境无需手动启动服务。点击 **检查准备情况** 只检查所需文件是否存在，不加载模型，也不保证依赖或音色质量合格。其他电脑先按下面的说明准备环境。
3. **选角色、写台词。** 从下拉框选择一二或布布。台词框已放入示例，可直接试用，也可以改成最多 1000 字的中文。建议先试一两句短句。
4. **生成并试听。** 点击窗口底部按钮，等待模型加载、合成和可选清晰化完成。生成期间桌宠继续活动；窗口内暂时不能修改配置。完成后停止本次生成服务、卸载模型，再进行可选清晰化、保存和播放。每次生成都重新加载，等待会比常驻服务更久。
5. **重播或下载。** “重播”播放当前角色本次窗口内最近生成的文件；“下载 WAV”另存该文件。切换角色会切换各自的最近输出。历史文件在高级设置 → **打开语音文件夹** 中。

**本机现有模型已配置，但窗口仍为空？** 先点 **重新读取配置**。也可点 **使用默认声音**：它会同时替换并保存两位角色的模型和参考录音配置，保留当前服务地址与语音偏好。已有自定义模型时不要用它代替保存。

**在其他电脑首次使用？** 仓库没有附带大模型或 Python 环境，不能凭空产生默认文件。按第 3 节准备匹配的模型与服务，再导入预设或在高级设置手动选择。未安装默认预设时，按钮会明确提示，不会假装已配置或自动下载。

### 1.3 轻度清晰化

默认勾选 **轻度清晰化**，采用此前试听版相同的温和均衡：65 Hz 高通、350 Hz 降低 2 dB、2600 Hz 提高 2.5 dB、4500 Hz 高频搁架提高 1.5 dB。以 -18 LUFS 为目标调整固定增益；若峰值余量不足，会优先限制在 -1.5 dBTP 以下，实际响度可能低于目标。

它不改变模型、音高或语速，也不是降噪或重新训练。可能减轻发闷，不能保证去除电音或修复丢失的发音细节。

- **新台词**：需要高级设置里有效的 `ffmpeg.exe`。原生成音先保存，清晰化后另存同名 `.clarity.wav`。试听和下载默认使用清晰化版；原音始终留在语音文件夹。
- **健康提醒**：两个版本都已随应用内容打包，勾选状态决定播放哪个版本；播放本身不需要 FFmpeg。
- **暂时关闭**：取消勾选即可自动保存，对下一次生成和下一条提醒生效。不会改写已经生成的文件，也不会切换正在播放的音频。
- **工具丢失或处理失败**：会提示原因，原音仍可重播、下载。可重新指定 FFmpeg，或取消勾选后再次生成。

### 1.4 导入预设、修改文件和保存

使用 **导入声音预设** 选择声音包中的 `voices.json`。预设须包含两位角色的模型路径、参考录音及逐字文字；支持相对于 JSON 所在文件夹的路径，导入时会转换为绝对路径并检查文件存在。大小写形式均可读取。失败时不替换原保存配置。

可参考仓库的 [预设模板](voice-preset.example.json)，将自己的文件放为：

```text
我的声音包/
  voices.json                # 复制模板并核对内容
  yier/gpt.ckpt
  yier/sovits.pth
  yier/reference.wav
  bubu/gpt.ckpt
  bubu/sovits.pth
  bubu/reference.wav
  tools/ffmpeg.exe            # 自行准备，可改成其他路径
```

模板里的参考文字对应本项目当前两段参考录音。如果换录音，必须一起改文字。示例模板不是可运行模型，不能只下载 JSON 就生成。

高级设置中的三个角色文件分别是：

| 字段 | 应填写的内容 |
| --- | --- |
| GPT 模型 | 该角色对应的 `.ckpt` 权重 |
| SoVITS 模型 | 与 GPT 及服务基础版本配套的 `.pth` 或 `.ckpt` |
| 参考录音 | 3–10 秒中文单人录音 |
| 参考录音文字 | 这段录音实际说的话，逐字一致；不是本次新台词 |
| 模型版本备注 | 例如 `v2`，仅作记录，不会自动替换服务模型 |
| 清晰化工具 | 本机 `ffmpeg.exe` 的完整路径 |

**保存配置**记录两位角色的路径、文字和偏好，不复制模型。**归档声音文件**复制当前角色的两个权重与参考音，保存校验清单，并将该角色配置改为归档路径。换角色后分别归档。生成时也会保存当前表单配置；勾选语音偏好会自动保存。

**停止播放**只停止音频；**取消生成**会取消本次请求并结束应用启动的服务。关闭语音工坊或退出应用也会结束本次按需服务。若音频已生成并进入清晰化保存阶段，该短暂处理会收尾，但关闭窗口后不再播放。桌宠不会自动安装 Python、下载基础模型或训练。

### 1.5 按需加载与资源占用

默认勾选高级设置中的 **按需启动，生成后立即卸载**：

| 操作 | 是否启动生成模型 |
| --- | --- |
| 启动桌宠、打开语音工坊、检查准备情况 | 否 |
| 播放健康提醒、重播、下载已生成音频 | 否，只访问本地 WAV |
| 点击生成并试听 | 是，临时启动 CPU 推理进程 |
| 生成完成、失败、超时、取消或关闭窗口 | 结束应用启动的推理进程 |

模型仍保留在硬盘，卸载指结束运行进程、释放其内存，不删除权重。CPU 推理限制为两条计算线程；生成期间仍会占用数 GB 内存和 CPU，按需启动减少的是日常常驻开销，不会让推理本身变得零开销。打开工坊不会做后台预热。

首次安装运行环境后，在高级设置填写：

1. **语音环境 Python**：安装好 GPT-SoVITS 依赖的 `python.exe`，不是随便一个系统 Python。
2. **GPT-SoVITS 根目录**：点击按钮选择其中的 `api_v2.py`，应用会填写所在目录。
3. **推理配置**：匹配角色版本的推理 YAML，包含基础模型、BERT 和 HuBERT 等路径。建议使用绝对路径；相对路径以 GPT-SoVITS 根目录为基准。
4. 保存后点 **检查准备情况**，再用短句试生成。

本机已填好现有独立环境。程序每次复制 YAML 后强制使用 CPU / 单精度，不改写原配置；启动器随应用放在 `Tools/voice_runtime.py`。它还监测桌宠进程退出，避免应用异常退出后模型长期残留。依赖与上游版本须兼容，其他版本需要实际验证。

默认地址是 `http://127.0.0.1:9880`。若端口被占用，程序会提示并停止启动，不会复用或结束其他服务。先关闭自己此前手动启动的服务，或更改端口。只有明确需要自行管理服务时，才取消按需选项；该外部服务的资源释放由用户负责，应用不会关闭它。

## 2. 为训练准备什么

建议先为每位角色建立独立目录：

```text
voice-training/
  yier/
    originals/       # 未改动的原始音频、视频
    clips/           # 分离、切分后的人声
    labels/          # 人工校对的文字标注
    reference/       # 参考录音及逐字文本
  bubu/
    originals/
    clips/
    labels/
    reference/
```

- 标清哪个声音是一二、哪个是布布，不混入另一位说话、旁白或不同配音版本。保留素材来源说明。
- 优先选无背景音乐、无回声、无重叠对话的单人声音；必须分离人声时也保留未处理的原件。分离产生的失真要人工听一遍。
- 我的准备建议是每位先收集 **5–10 分钟有效中文人声**，包含常用短句、疑问、开心等表达；这是为了覆盖更多发音和语气，不是上游规定的最低量或效果保证。官方展示了约 1 分钟数据微调的能力，但不等于任何一分钟素材都能达到目标。
- 每位预留一段清晰、连续的 **3–10 秒参考录音**，以及完全一致的文字。本次核对的上游推理代码有该时长检查。
- 单独保留少量验收台词，不用于挑选训练结果：招呼、关心、撒娇、较长句、数字和生僻字。之后分别评估音色、清晰度、语气和有无串音。

用户确认后的正式材料保存在 `voice-training/approved-20261014-04205443/`：一二 11 段（49.91 秒），布布 13 段（52.95 秒）。`labels/yier.list`、`labels/bubu.list` 分别提供两位角色的 GPT-SoVITS 标注；`references/` 保存各一段已确认素材中的参考音及文字。审核原件、音频校验与角色变更保存在该目录，原先未确定的 7 段已按用户确认结果纳入。

原始切分与机器标注草稿仍保留在 `voice-training/2026-10-14-six-videos/`，用于追溯，不代表当前审核状态。后续训练使用上述 approved 目录。这些本地音视频与模型缓存不纳入 Git。

本批素材主要是合成语音演示，两位各自的已确认素材都不足一分钟。角色与台词已由用户试听确认；训练后的音色、语气和长句稳定性仍需另行试听验收。

## 3. GPT-SoVITS 环境与训练

官方提供 Windows 整合包，也支持独立 Python 环境。请使用 [官方中文 README](https://github.com/RVC-Boss/GPT-SoVITS/blob/main/docs/cn/README.md) 的当前安装入口，避免改动其他项目已有的 Python 环境。下载基础模型时必须与选定版本配套。

本次于 2026-10-14 核对的上游提交：`1b47ca07ef43a284e0b8bd7f29d3e1e3ff76082a`。接口依据为该版本的 [api_v2.py](https://github.com/RVC-Boss/GPT-SoVITS/blob/1b47ca07ef43a284e0b8bd7f29d3e1e3ff76082a/api_v2.py)，配置参考 [tts_infer.yaml](https://github.com/RVC-Boss/GPT-SoVITS/blob/1b47ca07ef43a284e0b8bd7f29d3e1e3ff76082a/GPT_SoVITS/configs/tts_infer.yaml)。本机虽有 RTX 3070 Laptop GPU / 8 GB 显存，但 GPU 尝试受到 Windows 内存提交上限限制；按用户选择，最终在独立 Python 3.10.18 / PyTorch 2.5.1+cpu 环境完成 CPU 训练。

本次每位角色训练 SoVITS 2 轮、GPT 10 轮，批量分别为 1 和 2。为适配本机内存，数据加载使用主进程，SoVITS 随机训练窗口为 10240 个采样点（0.32 秒），关闭了本机出现原生崩溃的 MKLDNN 卷积路径。完整录音未截短，全部 24 段通过特征和训练过滤检查。修改补丁、实际配置、源码哈希、依赖版本及上游原结构日志均在本地保留。

本机结果目录为 `voice-training/trained-20261014-v2/`，两位角色各自的 GPT `.ckpt`、SoVITS `.pth`、`reference.wav` 和 `reference.txt` 分开保存。`model-verification.json` 记录最终轮数、文件哈希、有限数值检查以及相对基础模型实际发生变化的权重。后续输入不同文本直接使用这些权重，不需要再次训练。

以下是可选的手动调试方式；日常使用默认按需模式，不必执行。若要手动启动，请先在高级设置取消按需选项。本机已有环境可从项目根目录启动：

```powershell
.\voice-training\runtime\venv\Scripts\python.exe .\voice-training\runtime\serve_voice.py
```

也可运行 `voice-training/runtime/start_voice_service.ps1`。服务只监听 `127.0.0.1:9880`，使用本次验证的 CPU 设置；不要同时启动两份占用同一端口的服务。首次载入模型较慢，等服务就绪后再点击桌宠的“检查准备情况”。上述本地辅助脚本和运行环境不包含在 Git 仓库中；其他电脑仍按下面的官方流程准备环境。

两位角色均已用三句不在训练标注中的新台词生成 WAV，并使用相同参考录音和随机种子生成基础模型对照，共 12 条。结果目录中的 `试听对比.html` 可离线播放和下载，`training-curves.png` 展示训练损失。新文本试音和训练曲线不等于人工音色相似度验收。

首轮机器转写发现一二完整微调后的部分新台词偏差较大，因此补充中途权重和分别更换 GPT / SoVITS 的对照，累计保留 30 条开发试听。**微调并未稳定优于基础模型的转写表现，不能据此宣称音色或发音已经改善。** 当前一二暂用训练 10 轮的 GPT 配合基础 SoVITS，布布暂用 GPT 10 轮配合 SoVITS 2 轮。这是含已训练组件的组合中按三句开发台词转写结果暂选的配置；这些句子已用于选择，不能当作独立测试集。基础模型对照和全部原结果均保留。

另外通过桌宠实际的 `VoiceService` 和 `VoiceStore`，完成了两句未用于选择配置的新台词生成及 WAV 保存，并进行独立机器转写检查。记录见结果目录的 `desktop-client-verification.json`、`desktop-asr-evaluation.json`。这验证了真实本机接口与桌宠调用代码；音色还原度仍需用户试听。

本机已把试用配置写入语音工坊。如果窗口之前已经打开，请关闭后重新打开，以载入最新配置。模型备份包为 `voice-training/一二布布-声音模型-20261014-v2.zip`，包含试用权重、与试用配置不同的最终训练权重、参考音、试听页和验证记录；不包含 Python 环境或全部基础模型。

建议先以 v2 配套模型走通训练和推理，再根据试听效果决定是否换模型版本。不要直接混用不同版本的权重。训练按官方 WebUI 流程逐步进行：

1. 分别建立 `yier` 和 `bubu` 实验，导入各自的人声；需要时执行人声分离与切分。
2. 自动转写后人工逐条校对，检查说话者、文字和切片是否一致。
3. 提取训练所需的文本、音频及语义特征。
4. 分别训练 SoVITS 和 GPT，记录基础模型版本、训练配置、轮数与输出文件位置。先用小批量验证资源占用，遇到显存不足再减小批量。
5. 在官方推理界面用参考录音和新的验收台词试听，选择通过验收的一组匹配权重用于日常生成，同时保留训练记录和原始结果；不要仅凭训练结束就宣布音色合格。
6. 将选定的 GPT `.ckpt`、SoVITS `.pth`（或该版本对应的权重格式）及参考录音导入桌宠并归档。模型输出目录以所用官方版本实际显示为准。

在 GPT-SoVITS 根目录、对应 Python 环境中启动接口：

```powershell
python api_v2.py -a 127.0.0.1 -p 9880 -c GPT_SoVITS/configs/tts_infer.yaml
```

整合包使用其配套 Python；不要直接假定系统 `python` 已安装依赖。配置内的基础模型、设备、半精度及版本必须与实际环境匹配。运行接口时保留 GPT-SoVITS 目录结构和预训练模型。

桌宠先调用 `/set_gpt_weights` 和 `/set_sovits_weights`，然后 `POST /tts`，请求完整 WAV。一个服务只有一套当前权重，所以桌宠把这三个操作串行执行。**此服务应专供桌宠使用**，不要让其他客户端同时切换模型；窗口之间的排队无法控制其他程序。

备份时复制整个 `Voice` 目录；另行保存 GPT-SoVITS 环境版本、训练配置、原始素材及其基础模型。角色权重不是可独立运行的程序。换电脑或改变目录后，在界面重新选择三个文件并保存配置；配置使用绝对路径，不能假定旧电脑路径仍有效。

`manifest.json` 用于检查归档文件完整性；此清单不代表模型效果已验收，也不会每次推理都重新计算大模型哈希。归档只复制文件，桌宠本身不反序列化模型权重。

## 5. 常见问题与验证边界

- **准备检查通过但无法生成**：文件存在不代表依赖安装完整。按需启动失败会显示进程输出片段；核对 Python 环境、YAML 与基础模型。外部服务模式的连接检查使用 `/openapi.json`。
- **模型加载失败 / 服务返回 400**：查看错误详情，检查权重版本、基础模型以及参考录音。只保存空配置可以，生成和归档前必须补齐文件与参考文字。
- **超时或生成中连接中断**：按需模式会结束本次服务，下次点击会重新加载；可缩短台词或检查可用内存。外部服务模式可能仍在执行旧请求，需要自行重启服务和桌宠再试。启动最多等待三分钟；各接口请求也有三分钟超时，不自动重试生成。
- **声音不像 / 读错字**：需要回查素材、标注、选定权重和参考录音，不能只改接口参数就承诺解决。
- **能下载但听不到**：检查 Windows 音量和输出设备；播放失败不会删除已经生成的 WAV。
- **提醒没有声音**：检查该类提醒与“提醒时自动说话”是否都已开启、是否正在生成或试听、Windows 音量是否正常；只显示布布时会使用布布版本。素材缺失或播放失败不会阻断文字提醒，也不会临时调用模型。
- **默认声音文件移动了**：重新导入预设或在高级设置重新选择文件，保存后再试；程序不会猜测同名模型。
- **没有声音素材或模型**：可以配置和查看界面，但生成需要有效的模型、参考录音及本机服务。本次已完成本地训练和真实服务调用验证；这些权重与运行环境未随仓库或 v0.0.3 发布包分发，模拟接口测试也不能代替其他电脑上的真实生成验证。

开发结构：`VoiceStore` 保存配置、角色文件归档和 WAV；`VoiceService` 负责本机 API、权重切换排队、返回音频校验；`VoiceRuntime` 管理按需进程、取消与退出清理，`tools/voice_runtime.py` 在独立进程中加载上游 CPU 推理；`VoiceWindow` 提供配置、生成及试听界面。`VoiceAudioProcessor` 负责轻度清晰化，`ReminderVoice` 按角色和气泡全文的哈希匹配提醒音频。语音数据与表情库、现有宠物设置分开；健康提醒默认自动播报，可单独关闭。
